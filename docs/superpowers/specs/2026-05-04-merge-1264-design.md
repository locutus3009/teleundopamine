# Merge upstream release-12.6.4 into `nerovny/detox`

**Date:** 2026-05-04
**Sub-project:** A of three (B = sensitive-content lockdown; C = hashtag external-lookup loophole)
**Branch:** `nerovny/detox` (in-place merge; no worktree)
**Target:** `origin/master` (= upstream `release-12.6.4`, build 6666)

## Goal

Bring `nerovny/detox` from upstream version 12.5.1 (build 6580) up to 12.6.4 (build 6666) while preserving every custom anti-dopamine modification. Verification is code-level only: the user runs the build and on-device test pass after this sub-project plus sub-projects B and C all land.

## Non-goals

- New features. Sub-projects B (force-off + hide "Show 18+ Content") and C (close hashtag external-lookup loophole) are deferred to their own design/plan cycles.
- Build / runtime testing. The user does this once at the end, after all three sub-projects land.
- Refactoring. Custom code stays where it is unless upstream restructure forces relocation.

## Scope of the merge

`origin/master` is 6 commits ahead of `nerovny/detox`, spanning 573 files, ~46k insertions / ~20k deletions. Most of the volume comes from a new Kotlin `buildSrc/` directory that generates TLRPC types from a TL scheme — this is additive and unlikely to conflict directly. Direct conflicts are expected on every custom-modified file, with the heaviest in `ChatActivity.java` (~2000 lines changed upstream), `MessagesController.java` (~480 lines), and `ProfileActivity.java` (~130 lines).

## Approach: M2 — verify-during-resolve

A single merge commit, with semantic re-anchoring of custom blocks performed *during* conflict resolution rather than as a follow-up pass. This avoids the failure mode that produced commit `598bbcf26` ("Restore discussion/join blocking lost after merge"): conflicts that resolved textually but left custom guards attached to the wrong call-site.

### Workflow

1. **Inventory snapshot.** Generate working file `MERGE_INVENTORY.md` (uncommitted, scratch) listing every `// CUSTOM:` marker on `nerovny/detox` as `<file>:<line> <description>`. Ground truth for what must survive.
2. **Run the merge.** `git merge origin/master`.
3. **Per-file resolution + re-anchor pass.** For each conflicted file: resolve textually, then re-read the resolved file end-to-end and verify every inventory entry for that file is present and anchored to a call-site that performs the same user-visible action.
4. **Behavior cross-check.** After all conflicts close, walk the Feature → File Mapping table in CLAUDE.md and confirm each row's listed function still contains its `// CUSTOM:` block. Spot-check user-facing strings from the Feature Testing Checklist via grep.
5. **Single merge commit.** Message: `Merge upstream release-12.6.4 into nerovny/detox`.

### Per-file resolution rules

- **(a) Default: take both.** Keep upstream changes AND custom logic.
- **(b) Method renamed or split.** Re-anchor custom block to the equivalent user-facing flow in the new code. Add a one-line comment noting relocation: `// CUSTOM: <feature> (relocated from <old> — upstream split into <new> in 12.6.x)`.
- **(c) Method removed entirely.** Mark in `MERGE_INVENTORY.md` as **REMOVED** and pause for user decision. Do not silently drop.
- **(d) Custom block becomes redundant** (upstream added equivalent restriction). Keep our block anyway — preserves intent and guards against upstream reverts.
- **(e) TL schema shape changed.** Mark with `// MERGE-FLAG: verify TL shape` and list in `MERGE_INVENTORY.md` for the user's later compile pass to catch. Do not speculatively fix.
- **(f) Re-read whole file** after resolving conflicts in it.

## Deliverables

1. **Merge commit** on `nerovny/detox`: `Merge upstream release-12.6.4 into nerovny/detox`. Contains all conflict resolution and any in-merge re-anchoring required by rule (b).
2. **Follow-up commit** to CLAUDE.md (separate so the merge commit stays a pure resolution):
   - Adds a short "Post-merge verification" subsection under "Updating from Upstream" that directs future merges at the existing Feature → File Mapping and Feature Testing Checklist sections.
   - Updates "Current Base Version" line from `12.5.1 (build 6580)` to `12.6.4 (build 6666)`.
3. **Spec doc** (this file) committed at `docs/superpowers/specs/2026-05-04-merge-1264-design.md`.

`MERGE_INVENTORY.md` is a working artifact and is **not** committed; discard after verification passes.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Custom guard ends up on wrong call-site after upstream method rename/split | Per-file re-anchor pass during resolution (rule b) |
| Custom block silently dropped because upstream removed host method | Pause for user decision (rule c); never silent drop |
| TL type shape change breaks custom code referencing it | `// MERGE-FLAG` annotation surfaces at user's compile pass (rule e) |
| Existing hashtag-filter custom blocks (in `HashtagsSearchAdapter.java`, `PostsSearchContainer.java`) need re-anchoring | Treated as a normal rule (b) case; do **not** pre-emptively do sub-project C work in this merge |
| Existing sensitive-content infrastructure (`MessagesController` lines 21214, 23289–23339) gets rewritten by upstream | Untouched by us in this merge; sub-project B's override layers on top later |
| Unrelated changes ride along in the merge commit | Hard rule: only conflict resolution and rule (b) relocations land in the merge commit |

## What this design does not promise

- Does **not** prove behavioral correctness end-to-end. The cross-check is a smoke test that catches deletions, renames, and stranded guards; it cannot prove that the right conditional gates the right action. The per-file re-anchor pass (M2 Section 2) is the actual semantic check, performed by Claude with judgment.
- Does **not** verify the build compiles. User runs that pass after all three sub-projects land.
